기술

기술 개요와 안전 장치

어떻게 만들어졌고 무엇으로 막고 있는지 · 작성일 2026년 9월 25일

웹 페이지 하나와 구글 파이어베이스로 되어 있습니다. 서버를 직접 운영하지 않습니다. 자료는 서울 서버에 있고, 누가 무엇을 읽고 쓸 수 있는지는 서버 규칙이 정합니다.

1. 구성

부분쓰는 것하는 일
화면HTML 파일 하나모든 화면과 동작. 설치 없이 주소로 접속
배포Firebase Hosting주소 제공, HTTPS
로그인Firebase Authentication계정 확인, 비밀번호 보관
자료Cloud Firestore반·숙제·제출물·사진 보관
서버 위치asia-northeast3대한민국 서울

별도의 서버 프로그램이나 데이터베이스를 직접 운영하지 않아, 관리할 것이 적고 멈출 곳도 적습니다.

2. 자료가 놓인 모양

users/{계정} 이름, 역할, 소속 반 loginIds/{아이디} 아이디 → 계정 연결 classes/{반} 반 이름, 담당 선생님, 공지 └ students/{계정} 그 반 학생 └ homeworks/{숙제} 제목, 설명, 기한, 마감 여부 └ submissions/{제출} 낸 사람, 상태(대기·승인·반려) └ photos/{번호} 사진 (한 장이 한 칸) events/{일정} 학사 일정

사진을 한 장씩 따로 둔 이유는 한 칸에 담을 수 있는 크기에 제한이 있어서이고, 목록을 볼 때는 사진을 받아오지 않아 화면이 빨리 뜹니다.

3. 누가 무엇을 볼 수 있는가

화면에서 감추는 방식은 소용이 없습니다. 주소를 직접 부르면 그만이기 때문입니다. 그래서 서버가 거절하도록 규칙을 적어 두었습니다.

자료읽기쓰기
계정 정보본인, 그 반 담당 선생님본인
반·숙제그 반에 속한 사람담당 선생님
제출물낸 본인, 담당 선생님 학생은 자기 것만, 항상 '대기' 상태로만
제출 사진낸 본인, 담당 선생님낸 본인
승인·반려—담당 선생님만
가장 중요한 한 줄 — 학생이 보내는 제출물 저장 요청은 상태가 반드시 pending(대기)이어야 통과합니다. 이것 때문에 학생이 자기 숙제를 스스로 승인할 수 없습니다. 예전에는 가능했고, 점검에서 찾아 막았습니다.

규칙 원문은 파일럿/firestore.rules (89줄)에 있습니다.

4. 여러 기기가 어떻게 맞춰지는가

선생님이 승인하면 학생 화면이 새로고침 없이 바뀝니다. 서버의 변경 알림(구독)을 받아 화면을 다시 그리기 때문입니다. 선생님 휴대폰과 컴퓨터를 동시에 켜 두어도 같은 내용이 보입니다.

5. 비밀번호 보관

항목내용
저장 방식되돌릴 수 없게 변환해 저장(해시). 운영자도 알 수 없습니다
첫 비밀번호발급 시 모두 동일. 첫 로그인에서 반드시 변경
재설정계정 주소가 메일을 받을 수 없는 형식이라 메일 인증 불가. 운영자가 직접 설정

계정 주소에 한글을 쓸 수 없어 이름을 영문·숫자로 바꿔 만듭니다. 그래서 메일이 갈 수 없는 주소가 됩니다.

6. 비용

현재 규모(한 반 10명, 4주)에서는 구글 무료 사용량 안에 들어갑니다. 사진이 가장 많은 공간을 쓰므로 올릴 때 줄여서 저장합니다(한 장 약 1MB 이하).

7. 점검 체계

두 기기를 동시에 띄워 선생님·학생 흐름을 끝까지 돌리는 자동 점검 7종을 갖추고, 고칠 때마다 전부 다시 돌립니다.
  • 전체 흐름 — 계정 발급 → 숙제 → 제출 → 사진 → 승인 → 새로고침 후 유지
  • 권한 — 학생이 남의 제출물을 직접 요청하면 서버가 거절하는지
  • 구글 로그인, 아이디·비밀번호 변경, 계정 삭제
  • 숙제 수정·삭제·마감, 공지, 달력 표시, 넓은 화면
마지막 확인에서 7종 모두 통과했습니다.
