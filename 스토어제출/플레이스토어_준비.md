# 플레이스토어 제출 준비

앱 안에서 끝낸 것과, 사람이 직접 해야 하는 것을 나눠 적었습니다.

---

## 1. 먼저 채워 넣어야 할 곳

두 파일에 노란색으로 표시한 자리가 있습니다. **비워 두면 심사에서 반려됩니다.**

| 파일 | 채울 것 |
|---|---|
| `개인정보처리방침.html` | 개인정보 보호책임자 이름, 이메일 |
| `계정삭제요청.html` | 문의 이메일 |

## 2. 두 파일을 인터넷에 올리기

Play Console은 **접속 가능한 주소(URL)** 를 요구합니다. 파일만으로는 안 됩니다.

GitHub Pages가 가장 간단합니다 (무료):

1. GitHub에 공개 저장소를 하나 만듭니다
2. 두 HTML 파일을 올립니다
3. Settings → Pages → Source를 `main` 브랜치로 지정
4. 몇 분 뒤 아래 주소가 생깁니다

```
https://<아이디>.github.io/<저장소이름>/개인정보처리방침.html
https://<아이디>.github.io/<저장소이름>/계정삭제요청.html
```

> 한글 파일명이 불편하면 `privacy.html`, `delete.html`로 바꿔도 됩니다.

## 3. Play Console에 입력할 값

### 앱 콘텐츠 → 개인정보처리방침
```
위에서 만든 개인정보처리방침 주소
```

### 앱 콘텐츠 → 데이터 보안 (Data safety)

이 앱은 **서버가 없어서** 신고 내용이 단순합니다.

| 질문 | 답 |
|---|---|
| 데이터를 수집하거나 공유합니까? | **아니요** |

> 근거: 수집(collection)은 "데이터가 기기를 떠나 개발자에게 전송되는 것"을 뜻합니다.
> 이 앱은 전부 기기 안에만 저장하고 어디로도 보내지 않으므로 '수집 안 함'에 해당합니다.
> **나중에 파이어베이스를 붙이면 이 답이 전부 바뀝니다.** 그때 아래처럼 다시 신고해야 합니다.

<details>
<summary>파이어베이스 연동 후에 신고할 내용 (지금은 해당 없음)</summary>

| 데이터 유형 | 수집 | 공유 | 필수 | 목적 |
|---|---|---|---|---|
| 이름 | O | X | 필수 | 앱 기능 |
| 사진 | O | X | 선택 | 앱 기능 |
| 기타 (숙제 쪽지) | O | X | 선택 | 앱 기능 |

- 전송 중 암호화: 예
- 사용자가 삭제 요청 가능: 예
</details>

### 앱 콘텐츠 → 데이터 삭제
```
계정 삭제 요청 주소 (위에서 만든 것)
```
- "앱 내에서 계정을 삭제할 수 있습니까?" → **예** (마이페이지 > 계정 삭제)

### 앱 콘텐츠 → 타겟 layer 및 콘텐츠

- 타겟 연령대: **13세 미만 포함 여부를 신중히 고르세요**
  - 중학생만 대상이면 → 13–15세, 16–17세, 18세 이상
  - 초등학생도 쓴다면 → 5세 미만/5–8세/9–12세 포함 → **Families 정책**이 추가로 적용되어 심사가 훨씬 까다로워집니다
- 광고 포함: **아니요**

### 앱 콘텐츠 → 콘텐츠 등급 설문
- 카테고리: 교육 / 참고
- 폭력·성적 콘텐츠·비속어·도박: 전부 **아니요**
- 사용자 간 소통: **예** (학생이 선생님께 쪽지를 보냄) → 이 항목을 빠뜨리면 등급이 잘못 나옵니다

## 4. 아직 남은 문제 (스토어 정책 밖이지만 중요)

### 서버가 없어 앱으로선 작동하지 않음
선생님 폰과 학생 폰은 저장소가 따로입니다. 반 코드를 입력해도 상대 기기의 반을 찾을 수 없습니다.
**심사를 통과해도 실제로는 쓸 수 없으므로, 출시 전에 파이어베이스 연동이 반드시 필요합니다.**

### 관리자 비밀번호
소스에서 평문은 뺐고 관리자 화면에서 바꿀 수 있게 했지만, 네 자리 숫자는 앱을 뜯으면 금방 맞춰집니다.
**지나가다 눌러보는 사람을 막는 수준**이지 진짜 잠금이 아닙니다. 서버가 생기면 관리자 인증도 서버로 옮겨야 합니다.

### 웹뷰 래핑 반려 위험
HTML을 그대로 감싸기만 하면 "최소 기능" 정책으로 반려될 수 있습니다.
서버 연동 후 **PWA → TWA(Bubblewrap)** 방식을 권합니다.

### 앱 품질 (심사 반려보다는 혹평 요인)
- 안드로이드 뒤로가기: 지금은 홈에서 뒤로 누르면 앱이 종료됩니다
- 노치·제스처바: `safe-area-inset` 대응이 없어 화면이 가릴 수 있습니다
- 웹뷰에서 카메라 버튼: 네이티브 래퍼에 `onShowFileChooser` 연결이 필요합니다

## 5. 출시 절차 (개인 개발자 계정)

1. 개발자 계정 등록 ($25, 1회)
2. 앱 만들기 → 스토어 등록정보 (아이콘 512px, 그래픽 1024×500, 스크린샷 2장 이상)
3. 위 3번 항목 전부 입력
4. **비공개 테스트: 테스터 20명 이상 × 14일 연속** — 개인 계정은 이걸 마쳐야 프로덕션 신청이 열립니다
5. 프로덕션 심사 (보통 며칠 ~ 2주)

> 4번은 2023년 이후 개인 계정에 생긴 요건입니다. 정책은 자주 바뀌니 등록 시점에 Play Console 안내를 다시 확인하세요.

## 참고

여기 적은 개인정보처리방침은 이 앱의 실제 동작(서버 없음, 기기 안 저장)에 맞춰 쓴 초안입니다.
학원 등 사업자로 운영하실 거라면 사업자 정보를 넣고 한 번 검토받으시길 권합니다.
